API reference

The names on this page are OMBackend's public API: they are marked public and hold for all of 1.x. Nothing is exported: call them as OMBackend.name. Every other name is internal and may change in any release.

Translate

OMBackend.translate — Function
translate(model::OMJLIR.Model; mode = DEFAULT_BACKEND_MODE[], warnMissingStartValues = nothing,
          eliminateNonDynamic = nothing, observedFilter = nothing, checkSimCode = true)

The target code of a model another frontend lowered to OMJLIR and through its passes (OMBackend.Passes.runPasses!).

source
OMBackend.BackendMode — Type
BackendMode

How a scalar model is built: the keyword mode of translate, simulate and resimulate (DEFAULT_BACKEND_MODE[] when not given). IMTK_MODE (the default) or MTK_MODE. A model the arrays-kept path translated runs its own code in either mode.

source
OMBackend.IMTK_MODE — Constant
IMTK_MODE

The default BackendMode: the backend builds the ModelingToolkit system, simplifies it and builds the problem at translate time, and caches the build (CodeGeneration/IMTKGen.jl). A simulate remakes the cached problem. The mode of tunable parameters: withTunableParameters, and parameters of simulate and resimulate.

source
OMBackend.MTK_MODE — Constant
MTK_MODE

A BackendMode: the generated module is evaluated, its system simplified and its problem built at the first simulate. No tunable parameters.

source
OMBackend.SimCode.EliminationOptions — Type
EliminationOptions(; reachability = true, patterns = Regex[], keepPatterns = Regex[])

Options of the non-dynamic variable elimination (eliminateNonDynamic): the variables the dynamics do not need (not reachable from the state derivatives) are eliminated, all of them with reachability, else those matching patterns; never those matching keepPatterns.

source
OMBackend.explainIndexReduction — Function
explainIndexReduction(fm; functionList = nothing) -> Passes.IndexReduction.Explanation

What OMBackend's index reduction does to the flat model fm and why (Passes.IndexReduction.explain): the equations it differentiates and how often, the candidates of each choice with their StateSelect and the dummy derivatives among them, the states, the dynamic state sets; or why the model needs no reduction or is left to MTK. Planned as a translation would plan it, nothing translated.

source
OMBackend.scalarizedFallbackReason — Function
scalarizedFallbackReason(name) -> String

Why no arrays-kept path took the model name (canonical): the reasons the arrays-kept paths gave at its last translate (array index reduction, the array code after it, the backend's scalarization). OM's translate throws them (ARRAY_PRESERVING_CODEGEN_NOT_SUPPORTED); it no longer flattens a second time with scalarization (JKRT 2026-11-15).

source
OMBackend.canonicalName — Function
canonicalName(name::AbstractString) -> String

The name OMBackend keeps a model or a variable under: the dots of name replaced by _ ("Modelica.Blocks.Examples.PID_Controller" → "Modelica_Blocks_Examples_PID_Controller"), inside der(...) too. A quoted name ('a.b') stays as it is. The public functions take either form; the caches are keyed by this one.

source

Simulate

OMBackend.simulate — Function
simulate(modelName::String; mode = DEFAULT_BACKEND_MODE[], tspan = (0.0, 1.0), solver = defaultSolver(),
         overwriteCache = false, kwargs...) -> ODESolution

Simulate the translated model modelName (either name form, canonicalName) over tspan with solver (an OrdinaryDiffEq algorithm, Tsit5(); defaultSolver). mode is a BackendMode. overwriteCache rebuilds the problem. A run from another start time than the build's (translate builds at 0) builds at tspan[1] once; the next run from there reuses that build. parameters (name => value) sets parameters for this run: any parameter of a model the arrays-kept path translated, the parameters kept tunable at translate time (withTunableParameters, IMTK_MODE only) of another. The other keyword arguments go to solve. A violated assert throws ModelicaAssertionError.

OMBackend.simulate("HelloWorld"; tspan = (0.0, 2.0), reltol = 1e-6)
source
OMBackend.resimulate — Function
resimulate(modelName; solver, mode, tspan, parameters = Dict(), kwargs...)

Simulate an already compiled model again, without recompiling. parameters (name => value) sets the parameters isTunable names, as for simulate; other keyword arguments go to the solver.

source
OMBackend.getMTKProblem — Function
getMTKProblem(modelName; tspan=(0.0, 1.0), overwriteCache=false) -> Tuple

Build the problem of an already-translated model without solving it. Call OM.translate first. Returns the tuple of the generated model function; its first two elements are the ODEProblem and the model's event callbacks, which a solve needs too. The problem is the one simulate solves: after the runtime initial algorithm (the initial arms of when-equations: their parameter assignments, their hard starts), and one that ends at its start where a terminate() was reached at the initialization.

Example

OM.translate("Modelica.Mechanics.MultiBody.Examples.Elementary.Pendulum")
prob, callbacks = OMBackend.getMTKProblem("Modelica.Mechanics.MultiBody.Examples.Elementary.Pendulum")
sol = solve(prob, Rodas5P(); callback = callbacks)
source
OMBackend.defaultSolver — Function
defaultSolver()

The solver used when none is given: Rodas5P, with central finite-difference Jacobians. Rodas5's embedded error estimate misses a right-hand side that depends on time explicitly: on x' = cos(39t) it took 10 steps at reltol 1e-8 and ended far from the solution, where Rodas5P is right (SciML recommends Rodas5P over Rodas5). A mass-matrix system of a shape that Rosenbrock methods handle badly switches to daeFallbackSolver.

A Rosenbrock method (not a W-method) needs an accurate Jacobian for its order and its error estimate. Where the model has no symbolic one, forward differences were not accurate enough: MSL HeatingRectifier accepted a step across a diode's conduction onset with 25 times the tolerance in its error (Capacitor1.v 2.5 % off), where central differences, like ForwardDiff, give the reference. Finite differences, not ForwardDiff: external C functions take no dual numbers.

source
OMBackend.daeFallbackSolver — Function
daeFallbackSolver()

FBDF with finite-difference Jacobians: what the generated simulateFromBuild uses instead of a Rosenbrock method for purely algebraic systems and for algebraic rows of generated discrete variables.

variableValues(sols::Vector, variables...)

Similar to variableValues, but for solutions that have went through one or more structural changes. Here the same variable might have slightly different names depending on the context.

For instance it might be called M.A first and then M.B when the structure of the model is changed. In the example above a pendulum goes through once such change. Here you can specify the variables in order, they will be collected and merged into the final vector.

Example use:

OMBackend.eventCallbacks — Function
eventCallbacks(modelName) -> callbacks or nothing

The event callbacks of a translated model, as the second element of getMTKProblem's result.

  • A model the arrays-kept path translated: those of its problem over (0, 1) (it has no cached build: the problem, with its initialization, is built at each call). They include the run's bookkeeping callbacks (the start state, the first step).
  • Another: those of its cached build (IMTK_MODE), without building the problem again. The problem carries them as well (prob.kwargs[:callback], after any events of the MTK system), and a solve uses the problem's. nothing without a cached build.
source
OMBackend.CodeGeneration.isEventCallback — Function
isEventCallback(callback) -> Bool

Whether callback (of getMTKProblem's or eventCallbacks' callbacks, or of a problem's) is an event of the model: a relation's crossing, a when-condition, a sample, a delay's jump, a structural change. False for the algebraic step control (isStepControl), the assert checks and a run's bookkeeping callbacks (NotAnEvent). Counting the event callbacks of a model, one callback can hold several events (a vector of crossings). A solved problem's continuous callbacks merged into one (_eraseContinuousCallbacks) are an event where one of them is.

source
OMBackend.CodeGeneration.isStepControl — Function
isStepControl(callback) -> Bool

Whether a callback is the algebraic step control of a mass-matrix build (withAlgebraicStepControl), not an event callback.

source
OMBackend.CodeGeneration.ModelicaAssertionError — Type
ModelicaAssertionError(time, message, condition)

Thrown when a Modelica assert of level AssertionLevel.error (the default) is violated during a simulation.

source
OMBackend.plot — Function
plot(sol)

Plots a solution of OMBackend with Plots.jl: an OMSolution (all variables with their names), an OMSolutions (its sub solutions on the same graph, keywords legend, limX, limY), a vector of solutions, or any solution Plots can plot. The methods are added by the extension OMBackendPlotsExt, which Julia loads when Plots is loaded: using Plots (on Windows before OMBackend is loaded, see the head of src/OMBackend.jl). OM loads Plots itself.

Tunable parameters

Parameters kept symbolic at translate time, set again at each simulate without a new translation. OMSurrogates builds on these (parametric models, surrogates, neural blocks trained in the compiled model).

OMBackend.withTunableParameters — Function
withTunableParameters(f, names)

Run f() (a translate, or a simulate that compiles) with the parameters names kept as parameters of the generated model instead of being folded into its equations as constants, so the compiled model can be simulated again with other values of them. Parameters whose bindings depend on them are kept too. Names as in Modelica (body.m) or flattened (body_m). An array parameter (nn.W1, also a record field r.T or inside an array of components gs[1].g) is kept element by element, unused elements included; its elements are set one by one (nn.W1[2][1]), and uses of the whole array (e.g. a function argument, which the frontend expands) follow them. A tunable parameter read in an initial algorithm (evaluated at compile time) is an error.

OMBackend.withTunableParameters(["alpha", "beta"]) do
  OM.translate("LotkaVolterra", "lv.mo")
end
source
OMBackend.isTunable — Function
isTunable(modelName, names) -> Bool

Whether simulate(...; parameters) of the translated modelName can set all names without a new translation.

  • A model the arrays-kept path translated: every parameter it has, by name or element (k, k[2]; Modelica's or canonical names), except structural ones (array sizes, subscripts, if-equation conditions) and the parameters their bindings read.
  • Another: its cached build (IMTK_MODE) was compiled with all names tunable (withTunableParameters; an array as a whole) and has them as parameters. False without a cached build, or after the model was compiled again with other tunable parameters.
source
OMBackend.pristineParameters — Function
pristineParameters(modelName) -> Union{Nothing, Vector}

The parameter values the simulations of a translated model start from, a copy.

  • A model the arrays-kept path translated: the values (p.values, Vector{Float64}) of its problem over (0, 1), after its initialization (getMTKProblem builds it at each call). Its problems' parameters are more than these values (the run state): a new problem is getMTKProblem or simulate(...; parameters), not a remake with them.
  • Another: the parameter vector of its cached build (IMTK_MODE, cached at translate time). A simulation's solved problem (sol.prob.p) carries the vector as the event callbacks left it (if-condition switches flipped), so solving that problem again must start from this one (remake(sol.prob; p = pristineParameters(name))). nothing without a cached build.
source
OMBackend.buildId — Function
buildId(modelName) -> UInt64

The identity of the current build of the translated model modelName (either name form, canonicalName): the hash of the code translate generated for it. A translation that generates the same code keeps it; one that replaces the model by other code under the same name (other equations, other settings) changes it. A caller that keeps a build by name (a parametric model simulated by name) compares it with the identity of the build it made and translates again when they differ. An ArgumentError for a model not translated (availableModels).

Caches

OMBackend.clearCaches! — Function
clearCaches!(; models=true, implementations=true, wrappers=true, extractors=true)

Clear persistent caches. By default all caches are cleared. Use keyword arguments to selectively clear individual caches.

  • models: compiled MTK model ASTs, the cached builds and their external objects (tables), which their destructors free, and the modes compiled at structural changes (Runtime.RECOMPILED_MODES)
  • implementations: Modelica function implementations
  • wrappers: RTG wrapper functions for symbolic dispatch
  • extractors: per-element array extractor functions
source
OMBackend.forgetModel — Function
forgetModel(modelName::String) -> Nothing

Drops the cached build of one model and frees its external objects (tables) by their destructors, with its generated code and its run directory. For a long run over many models (a coverage worker): without it every model's build, tables and code stay for the whole session. A solution of the model that reads one of its tables afterwards throws; simulate the model again for a new one (a translate).
