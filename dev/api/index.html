API reference

The functions below are the user-facing part of the package (src/backendAPI.jl). The package has no export list for them: call them as OMBackend.name.

OMBackend.knownValues — Function
knownValues(model) -> Dict{Symbol, OMJLIR.Expression}

The algebraic variables of model the simulation code's first passes fold to a literal (a residual v - c, eliminated or not yet; a record function's output its interpretation finds constant), by their OMJLIR names: what index reduction plans with (Passes.IndexReduction.KNOWN_VALUES). SimCode of a copy of the model through the evaluation of constant function outputs (SimCode.simulationCodeThroughFunctionOutputs); empty where that fails.

Simulate

OMBackend.simulateModel — Function

simulateModel(modelName::String; MODE = DEFAULT_BACKEND_MODE[], tspan = (0.0, 1.0), solver = defaultSolver(), kwargs...) Simulates model interactively. The solver need to be passed with a : before the name, example: OMBackend.simulateModel(modelName, tspan = (0.0, 1.0), solver = :(Tsit5()));

source
OMBackend.resimulateModel — Function
resimulateModel(modelName; solver, tspan, parameters = Dict(), kwargs...)

Simulate an already compiled model again, without recompiling. parameters (name => value) sets parameters kept tunable at compile time (withTunableParameters); other keyword arguments go to the solver.

source
OMBackend.getMTKProblem — Function
getMTKProblem(modelName; tspan=(0.0, 1.0), overwriteCache=false) -> Tuple

Build the problem of an already-translated model without solving it. Call OM.translate first. Returns the tuple of the generated model function; its first two elements are the ODEProblem and the model's event callbacks, which a solve needs too. The problem is the one simulate solves: after the runtime initial algorithm (the initial arms of when-equations: their parameter assignments, their hard starts), and one that ends at its start where a terminate() was reached at the initialization.

Example

OM.translate("Modelica.Mechanics.MultiBody.Examples.Elementary.Pendulum")
prob, callbacks = OMBackend.getMTKProblem("Modelica.Mechanics.MultiBody.Examples.Elementary.Pendulum")
sol = solve(prob, Rodas5P(); callback = callbacks)
source
OMBackend.withTunableParameters — Function
withTunableParameters(f, names)

Run f() (a translate, or a simulate that compiles) with the parameters names kept as parameters of the generated model instead of being folded into its equations as constants, so the compiled model can be simulated again with other values of them. Parameters whose bindings depend on them are kept too. Names as in Modelica (body.m) or flattened (body_m). An array parameter (nn.W1, also a record field r.T or inside an array of components gs[1].g) is kept element by element, unused elements included; its elements are set one by one (nn.W1[2][1]), and uses of the whole array (e.g. a function argument, which the frontend expands) follow them. A tunable parameter read in an initial algorithm (evaluated at compile time) is an error.

OMBackend.withTunableParameters(["alpha", "beta"]) do
  OM.translate("LotkaVolterra", "lv.mo")
end
source
OMBackend.isTunable — Function
isTunable(modelName, names) -> Bool

Whether the compiled modelName (its cached build) was compiled with all names tunable (withTunableParameters; an array as a whole) and has them as parameters, so that simulate(...; parameters) can set them. False without a cached build, or after the model was compiled again with other tunable parameters.

source
OMBackend.eventCallbacks — Function
eventCallbacks(modelName) -> callbacks or nothing

The event callbacks of a compiled model's cached build (IMTK mode), as the second element of getMTKProblem's result, without building the problem again. The problem carries them as well (prob.kwargs[:callback], after any events of the MTK system), and a solve uses the problem's. nothing without a cached build.

source
OMBackend.pristineParameters — Function
pristineParameters(modelName) -> Vector or nothing

The parameter vector the simulations of a compiled model start from. A simulation's solved problem (sol.prob.p) carries the vector as the event callbacks left it (if-condition switches flipped), so solving that problem again must start from this one. nothing without a cached build (IMTK mode caches it at translate time).

source
OMBackend.plot — Function
plot(sol)

Plots a solution of OMBackend with Plots.jl: an OMSolution (all variables with their names), an OMSolutions (its sub solutions on the same graph, keywords legend, limX, limY), a vector of solutions, or any solution Plots can plot. The methods are added by the extension OMBackendPlotsExt, which Julia loads when Plots is loaded: using Plots (on Windows before OMBackend is loaded, see the head of src/OMBackend.jl). OM loads Plots itself.

Caches

OMBackend.clearCaches! — Function
clearCaches!(; models=true, implementations=true, wrappers=true, extractors=true)

Clear persistent caches. By default all caches are cleared. Use keyword arguments to selectively clear individual caches.

  • models: compiled MTK model ASTs, the cached builds and their external objects (tables), which their destructors free, and the modes compiled at structural changes (Runtime.RECOMPILED_MODES)
  • implementations: Modelica function implementations
  • wrappers: RTG wrapper functions for symbolic dispatch
  • extractors: per-element array extractor functions
source
OMBackend.forgetModel — Function
forgetModel(modelName::String) -> Nothing

Drops the cached build of one model and frees its external objects (tables) by their destructors, with its generated code and its run directory. For a long run over many models (a coverage worker): without it every model's build, tables and code stay for the whole session. A solution of the model that reads one of its tables afterwards throws; simulate the model again for a new one (a translate).
